# 小车运动与识别调参方案

在项目根目录编辑 [config/follow_settings.json](../config/follow_settings.json)，测试并部署后生效。这是车端的启动配置。JSON 里省略的参数沿用 [src/follow_settings.py](../src/follow_settings.py) 的默认值。控制页显示车头净距、当前限速原因、下发速度和里程计速度，可以用这些数据判断改动是否达到了预期。

## 不认主跟随的巡航速度

在 [控制页](http://127.0.0.1:8769/) 点击「启动不认主跟随」。小车优先保留正在跟随的人；人物消失时停车等待，已有目标消失持续 0.50 秒后才允许选择其他人。新目标需要连续画面确认后起步。

当前远距离巡航上限设为 **0.25 m/s（25 cm/s）**。这是现有底盘接口能接受的最高前进指令。默认要求人物在车头正前方约 ±5°、相机观测不超过 0.30 秒、雷达数据有效、连续确认人物距离且当前帧直接关联到人物回波。人物距离与雷达车身通道最近回波取较小值，作为巡航净距。

| 场景 | 默认前进指令上限 |
| --- | --- |
| 巡航净距达到 1.25 m，识别、雷达和电量均满足条件 | 0.25 m/s |
| 巡航净距在 1.00～1.25 m | 从 0.10 m/s 逐步过渡到 0.25 m/s |
| 净距不足 1.00 m、人物偏侧或雷达关联不确定 | 最多 0.10 m/s，并按角度、距离进一步降速 |
| 目标车头净距小于 0.60 m | 最多 0.05 m/s；目标停车距离为 0.30 m，制动余量会让停车指令提前 |
| 目标丢失、雷达数据过期或前方障碍进入停车范围 | 停车，等待条件恢复 |
| 电压低于 10.8 V | 最多 0.10 m/s；低于 10.5 V 持续 3 秒触发停车保护 |

转向限幅、加速度限制、障碍判断和指令看门狗参与每次计算。原厂几何已录入，制动实测标记仍为 `false`。普通跟随继续使用制动未实测时的低速档。把 `unlocked_cruise_mps` 设为 `0` 可以关闭这一巡航档。

## 调整车的走法

| 想调整的行为 | 配置项 | 默认值 | 调整方向 |
| --- | --- | --- | --- |
| 不认主远距离速度 | `unlocked_cruise_mps` | 0.25 m/s | 先用 0.15 或 0.20 找到合适手感。全局 `max_speed_mps` 仍是总上限 |
| 提前退出远距离巡航 | `unlocked_clearance_m` | 1.00 m | 提到 1.20 m 后，1.20 m 内回低速，1.45 m 起才有机会到全速 |
| 起步太冲 | `acceleration_mps2` | 0.30 m/s² | 试 0.20，车从静止加速到同样速度需要更长时间 |
| 距离稍变就急着追 | `forward_gain_per_s` | 0.65 | 试 0.50，使距离误差相同时的请求速度更低 |
| 左右来回摆 | `turn_deadband_deg`、`turn_gain_per_s` | 5°、0.90 | 先把转向死区加 1°，或把转向增益降到 0.75。远距离巡航仍要求在 ±5° 内 |
| 转弯太猛 | `angular_acceleration_rad_s2`、`max_turn_rad_s` | 0.60 rad/s²、0.25 rad/s | 先降低角加速度；若转弯峰值仍偏大，再降低最大角速度 |
| 偏侧时先对准再走 | `full_forward_angle_deg`、`turn_only_angle_deg` | 9°、12° | 例如设为 8°、11°。前进比例在这两个角度间从 100% 降到 0%，三个角度须按死区、减速起点、只转向递增 |
| 靠近后仍走得急 | `near_slowdown_m`、`approach_speed_mps` | 0.60 m、0.05 m/s | 把慢速段提前到 0.70 m，或把近距离速度降到 0.04 |
| 停车和恢复距离 | `stop_m`、`resume_m` | 0.30 m、0.40 m | 两值维持间隔，避免人在临界距离轻微摆动时反复启停 |
| 人暂时消失后多久可以换人 | `target_grace_s` | 0.50 s | 可试 0.70，拉长原目标重新出现的时间；等待期间仍停车 |

例如，想把起步和转向调柔和，把以下键合并进已有 JSON，保留文件里的安装标定字段。

```json
{
  "acceleration_mps2": 0.20,
  "turn_gain_per_s": 0.75,
  "angular_acceleration_rad_s2": 0.45
}
```

## 调整人物识别

| 现象 | 配置项 | 当前值 | 调法 |
| --- | --- | --- | --- |
| 中途转身或抬手时容易断轨 | `detection_min_confidence` | 0.10 | 可试 0.08。低分框可维持已有轨迹，建立新人物仍需达到新轨迹分数 |
| 容易把背景或局部肢体当作新人 | `tracking_new_confidence` | 0.35 | 先试 0.40。新目标会更慎重，弱光或远距离下可能更慢认出 |
| 同一个人出现重叠框 | `detection_nms_iou` | 0.70 | 可试 0.65。重叠抑制更强，两人交叉时也更容易合并框，需一起测试 |
| 普通跟随在人交叉时容易认错 | `reid_min_similarity`、`reid_min_margin` | 0.82、0.08 | 可先将其中一个提高到 0.85 或 0.10。前者提高同人外观要求，后者要求最佳和次佳候选差距更大 |

Re-ID 用于普通跟随的身份恢复。不认主跟随靠检测和轨迹连续性选人。每次改一组相关参数，在同一光线和路线下复跑。出现跳人先调检测与关联，人物框稳定但车身摆动再调转向。

## 修改、部署和复测

1. 在控制页停止当前会话，编辑 `config/follow_settings.json`。运行 `python -B -m pytest -q` 和 `python ops/build_release.py`。配置校验会拒绝越界数值，正确的包在 `releases/wheeltec-2.0.1.tar.gz`。
2. 按 [部署文档](deployment.md) 将归档上传到车端。在车端解出包内 `ops/deploy-on-robot.sh`，执行 `bash ops/deploy-on-robot.sh ~/wheeltec-2.0.1.tar.gz`。部署器会备份上个版本，重启后进入待机。电脑端继续使用 8769。
3. 先在控制页静止观察人物框、编号、净距和测距来源。再在前方空旷的平地验证直行、侧移、遮挡、障碍停车。高速验证从 0.15、0.20 到 0.25 m/s 分档做，每档记录下发和里程计速度、触发停车时的车头净距及实际静止位置。
4. 回放时看「计划 → 下发 → 里程计」。计划低，先看限速原因；计划高而下发低，检查加速坡度、电量和执行器；下发高而里程计低，再查底盘、路面或供电。完成 30 cm 停车验收前，保留实测前的制动标记。

调参后如果手感变差，把该项恢复到表里的默认值并重新构建部署。以车头到目标表面的实测距离为准，同时保留控制页和里程计记录。
